## Key creation

`store/installation_key.rs` is a private module, compiled on macOS or for unit
tests. Its coordinator uses the existing read/generate/create operations; it
never treats denial as absence, regenerates a malformed key, or retries a lost
winner by overwriting. The deterministic concurrent fixture forces two callers
to observe absence before either inserts, then requires both to return the
same published key. Read, randomness, creation, winner lookup and key length
failures have separate assertions.

The pinned security-framework 3.7.0 safe
`SecKeychain::default()?.add_generic_password` calls the create-only legacy
Keychain API without `set_generic_password`'s update fallback. The existing
SecItem query uses class/service/account without data-protection or sync
attributes; retain its default file-based macOS keychain policy rather than
silently migrating it. The native fixture must confirm add/get/duplicate
interoperability on the actual Mac. No unsafe code or dependencies were added.

Primary sources checked: security-framework 3.7.0
`os/macos/passwords.rs` (`add_generic_password`) and `os/macos/keychain.rs`
(`default`); `passwords_options.rs` (`new_generic_password`); Apple TN3137,
"On Mac keychains". These source reads are not OS execution evidence.

## FTE bootstrap

The existing Tauri setup callback invokes `storage::prepare` before managing
plugin state. Its default persistent path checks platform support before even
resolving a root; on Unix it creates a restrictive directory or hardens the
existing directory and synchronizes it before opening `gateway-v2.db`.
Static final-component files/symlinks are rejected before SQLite access.

Supplying a store without a default loopback needs no default disk root.
Supplying an explicit loopback does not touch the default root either; that
listener still owns and checks its explicit path when explicitly started.
An injected store plus default loopback prepares only the private root and
configuration, not a database, token or listener. Portable `SqliteStore` and
in-memory protocol behavior are unchanged.

This repairs bootstrap ordering within the existing local-path trust model.
It is not a claim of race-proof ancestor traversal, whole-store encryption, or
qualification of all FTE storage paths. No schema, model policy, dependency,
generated permission, listener-start behavior or migration was changed.
