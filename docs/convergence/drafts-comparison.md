# Drafts, autosave, and attachment ownership: Loom destination

Paired baseline: `1cee70d53605ba3bfba6a479e15eda308066ad21`. The implementation follows the later product decision: Mama Llama is deprecated; Loom (eventually Mine) is the sole destination. Do not add a shared autosave framework merely to keep Mom alive.

## Paired implementation judgment

| Concern | Mama Llama | Loom | Destination decision |
| --- | --- | --- | --- |
| Draft authority | `conversation_store.rs::draft_update` reads the entire DraftDb outside its later attachment lifecycle lock, edits one entry, then supplies a whole replacement to `attachments.rs::persist_drafts_with_attachment_gc`. | `loom-store/src/draft.rs::upsert_transient_draft` reads its addressed row inside an immediate SQLite transaction and validates source revision plus caller version. | Keep Loom's transactional row mutation. Mom's snapshot replacement loses unrelated concurrent edits even though the eventual encrypted writes commit together. |
| Retry correctness | No caller version. `updated_at` is presentation data, not a compare-and-swap token. | Store replay requires identical base version, source revision, and blob identity and then compares the actual slot bytes. The desktop adapter undermined this by accepting matching later text after a store conflict. | Remove the adapter exception. The store alone decides whether the exact write committed. This slice implements that deletion. |
| Storage size and crash phases | One encrypted DraftDb contains all composers; removed staged content can be reclaimed in the same SQLite transaction. | Two alternating bounded slots per document; the committed row chooses the authoritative slot. An uncommitted inactive-slot write cannot replace the current draft. Semantic revisions are not created on every keystroke. | Retain Loom's bounded draft storage and immutable semantic checkpoints. Do not persist chat keystrokes as a growing artifact history. |
| Clear and ABA | Clearing removes the draft with no monotonic sequence. Autosave can recreate or overwrite it without a version claim. | Persistent `transient_draft_sequences` survives clear/consume; stale versions cannot address recreated drafts. | Retain Loom's sequence and explicit caller claim. |
| Exact authored bytes | Mom saves the supplied string, but whitespace-only text without attachments is treated as absence. | Prose/verse draft slots preserve authored UTF-8 and line endings, including whitespace. Hybrid editing is refused at the desktop boundary until block metadata is preserved. | Keep exact bytes and fail closed for unsupported structure. The draft system must eventually store a structured chat draft, not flatten its roles or attachments into a text string. |
| Source and identity | The send path captures a DraftMessage snapshot and compares its exact message before admission. It commits messages, attachment ownership, draft changes, and optional journal together. | Draft writes validate the active immutable revision. Checkpoints consume a version/source/blob claim, optionally its exact committed successor after a lost acknowledgement. The checkpoint itself has a command receipt for exact replay. | Keep Loom's source/version/blob and command identity. Import Mom's attachment transfer into that same transaction when a native chat send path exists. |
| Edits while a run is working | `consume_exact_draft` removes the exact sent snapshot. If newer text exists, it keeps it and removes only attachment IDs transferred to the sent message. | A writing checkpoint refuses to consume a different draft; this is correct for explicit writing promotion. There is no active structured chat composer in the compared source. | Keep both semantics in their respective operations: exact writing checkpoint and asynchronous chat send. A chat send must never clear the user's newer composer text. Do not weaken writing CAS to imitate chat send behavior. |
| Draft attachment lifetime | Mom staged attachments are indexed separately from committed message attachments. GC verifies owned manifests and reference reachability before deleting encrypted objects, and conservatively retains unenumerable content. The import path also snapshots the draft/index before `put_documents_atomically`, so its stale whole-state writes should not be copied. | Loom's `context_attachments.rs` stores reusable document context and imported media separately from transient manuscript drafts. Draft blob identity currently covers writing bytes, not a set of transient message parts. | Adopt Mom's staged-versus-committed reference semantics for chat parts, under Loom's transaction and identity rules. Keep reusable document context distinct from one-message attachments. Do not delete a library/context object merely because a composer chip is removed. |
| Before a conversation exists | Mom supports `conversation_id: None` via `__new_chat__`; text survives before dispatch creates the conversation. | Transient drafts require a registered document and active revision. The desktop already opens an initial writing document automatically. | A future chat template should create a stable scratch document/session identity when opened, before the first send. The UI can remain blank and untitled; it need not ask the user to create a “conversation.” Promote the same identity on first send rather than move a global anonymous draft between owners. |
| Privacy | Mom encrypts draft text, manifests, objects, and journal documents at rest in its runtime store. | Loom deliberately keeps visible manuscripts ordinary UTF-8 and draft slots in its private project sidecar. | This is a deliberate storage difference, not parity achieved by this slice. If private chat drafts require encryption, implement a project privacy policy; do not encrypt or replace ordinary writing files silently. |

## Implemented replacement

`tauri-plugin-loom/src/lib.rs::document_draft_upsert` now delegates to a small production helper that validates the registered document, calls the existing store operation, and adapts its receipt/error. Removed the duplicate visible-text projection and the fallback that turned `TransientDraftVersionConflict` into apparent success based only on matching later text. No storage schema, Tauri payload, CLI, native engine, or Mom path changes are needed.

The practical failure was a same-content ABA sequence: A at version 1, B at version 2, A at version 3. Retrying the original A with expected version 0 used to return version 3 as `replayed: true`, despite version 3 having a different base. A stale renderer could consequently acquire a newer writer's version and proceed to overwrite from an obsolete state. The adapter now returns the store's conflict. A genuine exact lost-acknowledgement retry still returns the original version and blob identity.

## Reproductions and validation

- [Mom stale snapshot baseline](evidence/drafts-mom-baseline-overwrite.txt): deterministic two-snapshot interleaving expected two composers but recovered one. The test took two `load_drafts()` results, called `stage_in_draft` on different conversation IDs, and persisted each snapshot through the production GC persistence function. It exercises the exact interleaving of two draft-update calls without relying on thread scheduling. The temporary failing test was removed when Mom became the deprecated product; no Mom repair is claimed.
- [Loom replay baseline](evidence/drafts-loom-baseline-replay.txt): the production IPC match block was first extracted unchanged into its tested helper. The A/B/A regression failed, while the exact retry control passed. The fix then removed the conflicting adapter logic.
- Focused verification uses the two production helper tests and the existing complete `loom-store` draft test module. This establishes source/identity/replay behavior, bounded slots, clear/sequence behavior, immutable checkpoint consumption, and authored-byte recovery. It is not live editor or chat acceptance.

## Work still required for a full chat template

1. Add a native editable chat document/session path using the durable document graph. Importing a full snapshot as immutable evidence alongside a writing transcript does not implement active chat editing.
2. Give its draft a stable owner before the first message, and preserve it through template switches, close, and relaunch.
3. Make exact ordered text/media/tool parts part of the draft identity. Bind imported media to verified artifact IDs and content digests rather than filesystem strings or current selection.
4. At send admission, snapshot the branch source and exact draft claim. At commit, attach the committed parts and consume only that claim in the same transaction as the new messages and terminal receipt. Preserve later composer edits; detach only the parts actually committed.
5. Test staged/committed/shared attachment reachability, rollback after an attachment transfer, stale autosaves, source branch switches, lost acknowledgements, close during generation, and relaunch recovery through the actual chat interface.

These are complementary Mom behaviors to retain in Loom, not reasons to add a second document store or keep two desktop binaries. Advanced policy belongs in inspectable project settings/dotfiles while the ordinary composing and writing surfaces stay quiet.

Both used the team's shared target directory. `git diff --check` passed. Production adapter code is 12 lines smaller; regression tests add 75 lines. The temporary uncommitted shared-CAS/Mom expansion was removed completely before this slice was committed.
