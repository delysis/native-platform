# Mine integration review

This is an implementation review against `1cee70d53605ba3bfba6a479e15eda308066ad21`, with replacements on `codex/mom-loom-convergence`. The destination is Loom, becoming Mine. Mama Llama is deprecated and retained as a source of tested implementations and explicit imports. This branch does not yet replace every Mama capability or remove its executable.

## The architectural choice

Use Loom's document repository and desktop composition as the sole destination. Make a quiet writing page the default, with optional chat and expert panes described by `.mine.toml`. Offer a short, skippable configuration flow while an explicitly requested model download runs; its answers create the same editable dotfile. A chat turn is a document part with an explicit role, source occurrence, attachments and generation receipt. A prose passage is a part with exact source ranges and contribution history. Either may be projected into a transcript or a writing surface. Rendering headings does not manufacture message roles; changing a layout does not change storage policy, grant a tool, accept a candidate, or write a transcript file.

Keep three relationships distinct inside the document domain: conversation-context parentage, revision/edit parentage, and generation/adoption lineage. A single untyped parent field cannot express all three correctly. The document model must preserve all inactive alternatives, even when one selected branch is shown.

The best existing foundation is Loom's exact-content and revision machinery combined with Mom's typed conversation semantics, encrypted payload boundary, capability-bound tools and Persona snapshots. Move the useful Mama behavior into Loom, preserving exact evidence and explicit effect ownership. Shared pure modules are used where there are real consumers; new product behavior belongs to Loom. No new independent Mama feature work or third application is intended.

## Where deletion actually comes from

Extracting correct cores initially adds tests, validation and adapters. Removing a function from one product and adding it to a common crate is relocation, not net deletion. The review receipt must show actual added/deleted source lines, separate from documentation, and identify remaining duplicate command/rendering paths.

The large deletion comes after Mine owns the remaining Mama operations: retire one set of conversation/document mutation plumbing, one UI dispatch/refresh layer, one settings presentation stack, one model catalog adapter, and one desktop composition/packaging path. Keep unique capabilities such as revision provenance, Persona groups and Information citations. Do not trade those for an attractive line-count claim.

## Remaining cutover and acceptance

1. Use the shared durable document format for live typed chat commands, not only import. The present chat pane still concatenates history for a raw completion. It needs explicit role/template requests, version-bound append/edit/select commands, attachment-aware unsent drafts and complete branch navigation.
2. Port Mama's useful Persona history modes/groups, capability-bound tool execution, Information sources/citations, encrypted payload/cache protection, and exact receipts into the Loom command owner. Named sampling/context profiles alone are not complete Persona parity. Imported metadata is evidence, never a tool grant.
3. Finish mapping durable menu controls to `.mine.toml` and `.mine/personas/*.md`, with explicit commands for effects such as downloads, model reload, tool calls and exports. Existing advanced UI is retained until those consumers work. Do not hide an irreplaceable feature merely to make the screen simpler.
4. Exercise the actual Mine executable: configure during download, keep typing, skip setup, repair invalid TOML, reopen settings, choose/reload a model, branch a typed chat, discuss an exact manuscript selection, apply a frozen co-writer, use attachments, accept/dismiss inline completion, cancel, quit and reopen. Fixture/browser tests are not native model or bundle acceptance.
5. Retire Mama's mutation/rendering/composition code after these consumers exist, then measure net removal. Shared crates and a common codec do not by themselves establish identical binaries or complete feature parity.

The durable format now requires Loom store schema 16. A schema-15 store is refused at open before recovery or semantic writes; no in-place conversion runs. Ordinary manuscript files remain intact. This branch has only been exercised against disposable projects; do not claim existing-user-store or installed-app acceptance.
