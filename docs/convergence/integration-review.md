# Mama Llama and Loom integration review

This is an implementation review against `1cee70d53605ba3bfba6a479e15eda308066ad21`, with replacements on `codex/mom-loom-convergence`. It follows the request to combine the strongest implementations, including one document model. It is not a claim that two shipping applications have already become one binary.

## The architectural choice

Use one document domain, one desktop runtime composition, and two default layouts. A chat turn is a document part with an explicit role, source occurrence, attachments and generation receipt. A prose passage is a part with exact source ranges and contribution history. Either may be projected into a transcript or a writing surface. Rendering headings does not manufacture message roles; changing a layout does not change storage policy, grant a tool, accept a candidate, or write a transcript file.

Keep three relationships distinct inside the document domain: conversation-context parentage, revision/edit parentage, and generation/adoption lineage. A single untyped parent field cannot express all three correctly. The document model must preserve all inactive alternatives, even when one selected branch is shown.

The best existing foundation is Loom's exact-content and revision machinery combined with Mom's typed conversation semantics, encrypted payload boundary, capability-bound tools and Persona snapshots. Taking either whole app unchanged would lose essential features of the other. New common modules should own actual decisions with both consumers, not mirror both old records under an enum.

## Where deletion actually comes from

Extracting correct cores initially adds tests, validation and adapters. Removing a function from one product and adding it to a common crate is relocation, not net deletion. The review receipt must show actual added/deleted source lines, separate from documentation, and identify remaining duplicate command/rendering paths.

The large deletion comes after both layouts use the same document command owner: retire one set of conversation/document mutation plumbing, one UI dispatch/refresh layer, one settings presentation stack, one model catalog adapter, and one desktop composition/packaging path. Keep unique capabilities such as revision provenance, Persona groups and Information citations. Do not trade those for an attractive line-count claim.

## Next cutover and acceptance

1. Finish the common durable document codec and shared mutation commands. Preserve original IDs as typed source identities and forbid decoding incompatible source stores as empty. Existing source files remain intact; imports are explicit.
2. Move drafts to one version/source/content protocol. Exercise two windows, delayed saves, send versus autosave, exact lost-ack retries, attachment removal, restart and version reuse. This is required before allowing both layouts to edit the same live document.
3. Put Mom's chat/Persona/tool operations behind the shared document repository; expose source-bound manuscript selections to those operations. A tool result must retain its receipt and role when viewed or edited as writing.
4. Make Chat and Write actual layout templates in one shell. Chat must open without creating a manuscript file; Write must preserve exact text and candidate acceptance. Switching layouts must not change the document's protection policy or content.
5. Run the combined product: branch a chat, view it as writing, edit a response while retaining original generation provenance, discuss an exact manuscript selection, apply a frozen co-writer, use attachments, accept/dismiss inline completion, cancel a run, quit and reopen both views. Verify the exact executable, assets and source revision for that acceptance.
6. Delete former mutation/rendering/composition code once these consumers are gone, then measure net removal. Identical binaries means one build artifact and one update channel, not two separately configured app builds from similar sources.

This ordering keeps implementation reviewable and avoids building a third unused application alongside the current two.
