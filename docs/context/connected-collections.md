# Retained connected collections

A collection names one explicitly selected Drive folder or Gmail query. It is
one navigable source, not a group of account controls in the sidebar. Opening,
searching, pinning, and referencing retained content perform no network requests.
Drive scope currently means eligible direct children, not recursive traversal.

Definitions live in the existing `.loom.md` configuration. Revision-checked edits
preserve unrelated Markdown, settings, and pane visibility. A copied definition
carries no acquisition authority. Local grants bind canonical workspace root,
project identity, collection identity, selected account, provider, and exact
scope. Credentials remain in the OS credential store. Reconnection presents the
scope and requires an explicit account; it does not start acquisition.

Refresh is an owned backend job with joined shutdown, session validation, and
cancellation at publication. Closing the view only detaches its observer. A job
checkpoints its bounded provider page before downloading sources. Immutable
attachments, acquisition receipts, and membership snapshots precede one atomic
head replacement. Stop prevents later publication; completed members remain
readable. Interrupted jobs require explicit Resume. Start again performs a fresh
listing when a continuation is unavailable or expired. No migration or silent
background acquisition is performed.

Occurrence identity is provider + selected principal + remote item ID; attachment
identity is exact retained bytes. Identical files at two remote IDs keep separate
occurrences and receipts. A refresh can replace an occurrence's current version
without changing prior snapshots, previews, citations, or inference inputs.
Provider modification timestamps are observations, not integrity witnesses.
A completed mutable listing is not a point-in-time account snapshot. Failed or
unobserved sources are retained, never inferred to be deleted.

Context planning freezes the membership snapshot before retrieval. Local search
shares the operation's 8 MiB scan allowance, returns at most 12 passages / 24 KiB,
and records omitted occurrences. Collection values are not silently coerced into
exact function arguments. Evidence retains snapshot, occurrence, attachment,
origin receipt, source URI, exact text coordinates, and mapped PDF pages. Image
and audio preview authority binds workspace session, collection, immutable
snapshot, occurrence, and media hash; removal revokes preview access while prior
evidence remains readable.

Checks cover immutable versions, distinct occurrences with identical bytes,
interrupted continuation, failed members, copied-root/scope grant refusal,
publication failure, frozen offline search, bounded omissions, media version
binding/revocation, configuration edits, joined worker ownership, and browser
navigation. These are component and local integration checks. Real provider
refresh/restart and packaged macOS interaction acceptance remain separate.

Ordinary materials and collection definitions share the revision-checked `.loom.md`
fence. Metadata rename, pin and removal require the observed native generation,
including the file and workspace directory identities. Full material-ID links
survive display-name changes. A pending visible-file projection is a retained
failure, not an acknowledged configuration change.

Legacy material definitions are adopted and archived from one anchored read;
replacement or invalid metadata fails closed. The original bytes remain under a
content-addressed archive name before the old registration filename is retired.
This adds no second writable configuration owner or persisted-format migration
reader. Collection acquisition grants are retired only after a fresh, accepted
definition removal; retained members, evidence and account credentials survive.
