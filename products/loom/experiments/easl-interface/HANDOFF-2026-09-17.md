# Native EASL Loom handoff — September 17, 2026

## Readiness

**Usable for experimental text editing; not a replacement for the current Loom
application.** The native host, lossless Markdown model and reusable EASL text
policies are implemented. Application adapters, a complete EASL atlas widget,
latest-upstream UI reconciliation and final native acceptance are unfinished.
Do not interpret a successful build, offscreen image or component test as those
missing capabilities. No new foreground window was opened or driven for this
handoff. Existing review windows may run older executables.

The user requested that development stop at a verified checkpoint, be pushed,
and be handed off with the remaining work. This checkpoint completes the pending
formatting/link-input work; it does not claim the original parity goal complete.

## What is implemented

- Standalone macOS native window, current reviewed titlebar assets, native editor
  painting, light/dark appearances, configured main/right/bottom editor panes,
  source/visual modes, shared source/history and pane-local caret/scroll/layout.
- Async ordinary-folder project open/create/select/save through the shared store
  and session worker, exact UTF-8/CRLF preservation, conditional persistence,
  bounded recovery and shutdown contracts. Existing document identity is reused.
- Native lossless Markdown editing: headings, emphasis, links, quotes, nested
  lists, code, input rules, structural transactions, tracked selections and undo.
  Unsupported transactions fail instead of silently rewriting source.
- The final formatting palette retains document/revision/pane-bound selections,
  active states, accessible names, paragraph and emphasis/list commands. Its
  Link destination/Link/Remove row has literal single-line input, independent
  undo, horizontal caret reveal, pointer/keyboard routing and IME ownership.
  Unlink removes selected linked edge spaces. Invalid/stale commands preserve
  the manuscript. Bold/italic command labels use the reference typography.
- Native focus identities, Tab traversal, pane selectors and bounded splitters;
  AccessKit semantics and an optional independent Wry child webview. Actual
  combined OS focus/accessibility qualification remains outstanding.
- Importable EASL paragraph composition, editing/history/preedit, geometry,
  navigation, script/bidi/run planning, fallback, rich styles, page selection,
  glyph placement and viewport modules; native font opening, contextual shaping,
  selected-glyph Swash pages and immutable texture residency primitives.
- Actual Loom use of shared EASL edit, hit-test, navigation, rich-style and final
  glyph/decorations policies. Loom still uses Parley line/caret layout and Vello
  CPU rasterization. The standalone EASL atlas widget is a separate bounded path.
- Width-only reflow reuses shaped runs. Earlier synthetic measurements reduced
  175 KB resize median from 62.672 ms to 1.993 ms, excluding painting and OS input.
  The original extreme slowdown was principally unoptimized CPU rasterization,
  plus unnecessary repaints. See [PERFORMANCE.md](PERFORMANCE.md); none of these
  samples establishes current end-to-end typing latency.

| Reusable EASL library | `crates/services/easl/easl-text/library`, with bounded Rust transports under `src` |

| Existing application services to adapt | `products/loom/crates/tauri-plugin-loom/src` and shared native-kit services |

Application/configuration/model authority stays in Rust services. The text
widget emits view edits/actions; it does not gain persistence, credentials,
model lifecycle or project policy authority. Some Tauri/native orchestration
still needs extraction; that architectural work is not finished merely because
both adapters call the same store. There is no separate experimental preference
format or invented context manuscript.

## Run and verify

Use Rust 1.92.0 and the optimized `native-view` profile. Do not use a plain debug
build for interactive performance conclusions. From the repository root:

```sh
EASL_BUILD_COMMIT=$(git rev-parse HEAD) rustup run 1.92.0 cargo run --locked --profile native-view -p loom-easl-interface -- --build-info
EASL_BUILD_COMMIT=$(git rev-parse HEAD) rustup run 1.92.0 cargo run --locked --profile native-view -p loom-easl-interface -- --project /absolute/path/to/synthetic-project
```

The second command opens a window; run only when foreground testing is wanted.
On macOS add `--webview` for the independent Wry child. `--ui` selects an EASL
view source and F5 validates/reloads it. Follow `products/loom/AGENTS.md` for a
stable signed repeated-use bundle. Use synthetic projects during acceptance;
do not mutate existing manuscripts or automate unrelated windows.

Full component checks (offscreen GPU tests need a native GPU):

```sh
rustup run 1.92.0 cargo test --locked --profile native-view -p loom-markdown -p loom-easl-interface -p easl-text -p easl-native-text -p fsexp --features easl-text/gpu
rustup run 1.92.0 cargo clippy --locked --profile native-view -p loom-markdown -p loom-easl-interface -p easl-text -p easl-native-text --features easl-text/gpu --all-targets -- -D warnings
rustup run 1.92.0 cargo run --locked --profile native-view -p xtask -- policy
rustup run 1.92.0 cargo fmt --all -- --check
```

Use one Cargo process at a time and reuse one target directory/feature union.
Do not add vendor packages to workspace membership or create vendor lockfiles.
The historical shared local target directory contains `easl-studio` in its path;
that is a cache name, not a linked dependency or shipped application.
